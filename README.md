# Codex Quota Estimate（Codex 额度估算）

[English](README.en.md) | 中文

![version](https://img.shields.io/badge/version-v0.1-blue)
![license](https://img.shields.io/badge/license-MIT-green)
![userscript](https://img.shields.io/badge/userscript-Tampermonkey%20%7C%20Violentmonkey%20%7C%20ScriptCat-orange)

一个油猴脚本：在 ChatGPT 的 **用量（Usage）页面**查看 Codex 额度窗口，按 OpenAI 官方费率把各模型的 Token 用量折算成美元，并估算本周还剩多少额度（折合美元）。

官方页面只告诉你「周额度用了 37%」，这个脚本进一步回答：

- 这 37% 大约值多少钱？
- 整周的额度大约折合多少美元，还剩多少？
- 钱主要花在了哪个模型、哪个客户端（桌面应用、CLI、IDE 插件、网页）上？

> ⚠️ 本项目**不是** OpenAI 官方工具，与 OpenAI 无关。脚本依赖 ChatGPT 网页内部使用的未公开接口，OpenAI 随时可能变更，届时脚本可能失效。估算结果仅供参考，详见[局限性](#局限性请务必阅读)。

## 功能

- **额度窗口**：用进度条显示 5 小时窗口和周窗口的剩余比例，以及本地时间的重置时间。没有 5 小时限制的套餐显示「无此限制」。
- **本周期概览**：剩余额度估算（美元）、周额度估值、本周期已消耗金额、Token 数和对话轮数。
- **模型构成**：本周期各模型、各速度档位的轮数、Token 数、金额和占比。Plus / Pro 账号的模型明细只有轮数；本周期还没有模型明细时会显示说明。
- **使用来源**：本周期各来源的轮数、Token 数、金额和占比，归并为：
  - Desktop：桌面应用、Work 桌面端
  - CLI：含 `codex exec`、service_exec、SDK
  - Plugin：VS Code、JetBrains 等 IDE 插件
  - Web：网页、手机
  - 其他：Slack、GitHub 等集成

  Plus / Pro 账号可以在这里看到按官方 credits 拆分的金额。
- **每日明细**：最近 30 天每天的 Token、金额和轮数。本周期和之前的日子之间有一行分隔，两部分各有合计。鼠标悬停在金额上，可以看到按模型拆分的明细。
- **结果可靠性提示**：以下情况会给出提示：
  - 周百分比太低；
  - 数据来自整个工作区；
  - 出现费率表中没有的模型。
- **多工作区**：自动使用你当前所在的工作区（个人或某个 Team），切换 Team 后刷新即可。
- **无权限时降级显示**：如果当前账号无权读取工作区用量统计（通常只有管理员可以查看），仍会显示额度百分比，只是没有金额。
- **右下角按钮**：读取一次后，按钮上会直接显示周剩余比例和估算的剩余金额。
- **界面**：
  - 侧边抽屉式面板，用 emoji 和颜色区分剩余多少（🟢 充足 / 🟡 一般 / 🔴 紧张）；
  - 用 Shadow DOM 与页面样式隔离，跟随 ChatGPT 的深色 / 浅色主题；
  - 可以随时刷新，按 `Esc` 关闭。

### 更新与卸载

- **更新**：从 Greasy Fork 或 raw 链接安装的脚本，会由脚本管理器定期检查更新，也可以在管理器里手动点「检查更新」。
- **卸载**：在脚本管理器的列表中删除即可。脚本不在浏览器里保存任何数据，删除后没有残留。

## 使用

1. 登录 ChatGPT，打开 **设置 → 用量**（`https://chatgpt.com/settings/usage`）。
2. 点击右下角的 **🧭 Codex 额度估算** 按钮，右侧会滑出面板。
3. 面板标题栏有两个按钮：↻ 重新读取数据，✕ 关闭面板（也可以按 `Esc`）。

**数据什么时候更新：** 脚本不会在后台自动读取数据，只在两种情况下读取：

- 打开面板时；
- 点击 ↻ 时。

每次读取都会按接口返回的重置时间，重新计算周期。如果面板一直开着，期间刚好跨过了周额度重置时间，要点一下 ↻ 才会切换到新周期。右下角按钮上的数字也一样，显示的是上次读取时的结果。

## 面板说明

| 区域 | 内容 |
|---|---|
| 顶部 | 账号类型（个人套餐 / 工作区套餐）、当前周期的起止日期 |
| 额度窗口 | 5 小时窗口和周窗口的剩余百分比、重置时间。颜色规则：剩余 > 50% 为 🟢，> 20% 为 🟡，其余为 🔴 |
| 本周期概览 | 剩余额度估算、周额度估值、已消耗金额、Token 数、轮数 |
| 提示 | 黄色提示条，说明本次结果可能不准的原因 |
| 模型构成 / 使用来源 | 本周期的金额分别按模型和按来源拆分 |
| 每日明细 | 最近 30 天的逐日数据。带 `*` 的金额不完整，原因见[常见问题](#常见问题) |

## 计算方法

### 已消耗金额

脚本先根据账号类型（接口返回的 `plan_type`）决定计算方式，因为两类账号返回的数据结构不同：

| 账号类型 | 接口数据特点 | 计算方式 |
|---|---|---|
| **个人套餐**：Plus、Pro（以及 Go、Free） | 每天的总计带官方 `credits`，模型明细只有轮数 | `credits × $0.04`。没有 credits 的日子不计入金额，标 `*` |
| **工作区套餐**：Team（以及 Business、Enterprise、Edu） | `credits` 不含套餐内用量（为 0，或只有超额付费部分），模型明细带各项 Token | 各模型 Token × 官方费率（见下方公式）。模型明细缺少 Token 时才退回 credits |
| 未识别的类型 | — | 有 credits 用 credits，否则按 Token 计算 |

面板顶部会显示账号类型。分组规则在脚本开头的 `PLAN_GROUPS` 中。其中 Go、Free、Business、Enterprise、Edu 的归类是按套餐性质推断的，尚未用真实数据验证。如果你使用这些套餐，欢迎反馈结果是否合理。

按 Token 计算时的公式：

OpenAI 的 [Codex 费率表](https://learn.chatgpt.com/docs/pricing) 给出了每个模型每百万 Token 消耗多少 credits。按 1 credit = $0.04 换算后，与 [OpenAI API 标准价](https://developers.openai.com/api/docs/pricing) 完全一致，所以脚本直接使用 API 的美元单价：

```
金额 = (未缓存输入 × 输入单价 + 缓存输入 × 缓存单价 + 输出 × 输出单价) ÷ 1,000,000 × 速度倍率
```

速度倍率与官方返回的 credits 保持一致：standard 为 1 倍，fast 为 2 倍，ultrafast 为 6 倍。实测 Fast 模式的官方 credits 正好是标准速度的 2 倍。

### 周额度估值与剩余额度

```
周额度估值 = 本周期已消耗金额 ÷ (周窗口已用百分比 ÷ 100)
剩余额度   = 周额度估值 − 本周期已消耗金额
```

**例子：** 本周期已消耗 $12，周窗口已用 40%。

- 周额度估值 = 12 ÷ 0.4 = $30
- 剩余额度 = 30 − 12 = $18

本周期从周窗口的 `reset_at − limit_window_seconds` 开始计算，按本地日期划分。

### 数据来源

脚本只请求 chatgpt.com 自己的接口：

| 接口 | 用途 |
|---|---|
| `/api/auth/session` | 获取当前登录会话的访问令牌和工作区 ID |
| `/backend-api/wham/usage` | 5 小时窗口和周窗口的已用百分比、重置时间 |
| `/backend-api/wham/analytics/daily-workspace-usage-counts` | 每天的 credits、Token 和轮数（总计、各模型、各客户端） |
| `/backend-api/wham/usage/daily-token-usage-breakdown` | 每天各模型、各使用来源的用量占比（与官方「使用情况 → 分析 → 按模型」一致），用于模型构成和使用来源的金额拆分 |

## 局限性（请务必阅读）

1. **工作区数据混在一起**：每日用量接口返回的是**整个工作区**的数据，而百分比反映的是**你本人**的额度。如果工作区里还有其他人在使用（比如 Team / Business 套餐），估值会偏高。
2. **线性关系未经官方确认**：「已消耗 ÷ 百分比 = 周额度」是一种推断。OpenAI 没有公布周额度的具体数值，也没有说明额度是否完全按 API 价格扣减。
3. **只有整数百分比**：接口只返回整数百分比。周百分比很低（比如 1%）时，估值可能相差好几倍。
4. **不计 Token 以外的消耗**：如果云端任务的运行时长、工具调用等也会扣额度，按 Token 计算会漏掉这部分。
5. **周期起始日按整天统计**：接口按天汇总用量，而周额度是在某个时刻重置的。周期起始当天的用量里可能混有重置之前的部分，此时估值会偏高，面板会给出提示。
6. **费率需要维护**：OpenAI 上线新模型或调整价格后，需要更新 `PRICE_ROWS`。没有定价的模型不计入金额，面板会给出提示。

所以周额度估值只能作为大致参考，不代表 OpenAI 承诺的额度。一周里用得越多，周百分比越高，估值越稳定。

## 隐私与安全

- 访问令牌**只用于请求 chatgpt.com 自己的接口**。
- 所有数据只在你的浏览器内处理，**不会发送给任何第三方**，也不会写入本地存储。
- 只在你打开面板或点击 ↻ 时请求一次（共 4 个接口），不会在后台轮询。
- 脚本不需要任何特殊权限（`@grant none`），代码没有混淆或压缩，可以直接审阅。

## 配置

可以修改脚本开头的常量：

| 常量 | 说明 |
|---|---|
| `PRICE_ROWS` | 各模型的单价，每行依次为模型名前缀、输入、缓存输入、输出（美元 / 百万 Token）。匹配时取最长的前缀。 |
| `EXCLUDED_MODELS` | 不计入周额度、也不提示缺少定价的模型，默认包含 `codex-auto-review`（代码审查有独立的限额）。 |
| `PRICES_CHECKED` | 价格最后核对的日期（仅作记录）。 |
| `SPEED_FACTOR` | 速度倍率。 |
| `PLAN_GROUPS` | 账号类型分组，决定按 credits 还是按 Token 计算。 |
| `LOOKBACK_DAYS` | 读取多少天的历史数据，默认 30 天。 |
| `LOW_PERCENT` | 周百分比低于这个值时提示误差较大，默认为 5。 |

> 直接修改脚本后，脚本管理器自动更新时会覆盖你的改动。如果只是价格过时，建议提交 Issue 或 PR，让所有人都能用上新价格。

## 常见问题

**看不到按钮？**

按钮只在用量页面显示。请确认：

- 脚本已启用；
- 当前地址是以下之一：`/settings/usage`、`/codex/settings/analytics`、`/codex/cloud/settings/analytics`，或者地址里带有 `#settings/Usage`；
- 如果用的是 Chrome / Edge 上的 Tampermonkey，已经打开了「允许运行用户脚本」。

**提示「没有读取到登录状态」或「读取失败：接口 … 返回 HTTP 401」？**

登录状态过期了。刷新页面或重新登录 ChatGPT。

**提示「当前账号无权读取工作区用量统计」？**

你是 Team 等工作区里的普通成员，每日用量接口只对管理员开放。此时只能看到额度百分比，没有金额。

**提示「读取失败：接口 … 返回 HTTP 404」？**

OpenAI 修改了接口，请提交 Issue。

**某天的金额后面带 `*`？**

当天有未定价的模型，或者缺少模型明细，这部分没有计入金额。

**周额度刚重置，面板上的数字没变？**

面板不会自动刷新，点一下 ↻ 即可。

**估值和别人的差很多？**

周额度估值和这些因素有关：

- 套餐类型；
- 本周期用了多少（百分比越低，误差越大）；
- 工作区里是否有其他人在用。

不同账号之间差别大是正常的。参见[局限性](#局限性请务必阅读)。

**会不会导致封号？**

脚本只是在你打开面板时，用你自己的登录状态请求几次 ChatGPT 网页本身就会请求的接口，请求频率和手动刷新用量页面差不多。不过，这仍然是非官方工具，使用风险请自行判断。
